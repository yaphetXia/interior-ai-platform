## 🆚 新旧架构对比

### 旧架构（硬编码）

```javascript
// ❌ 硬编码模板
function buildFurniturePrompt({ userInput, keywords }) {
  const action = translated.actions[0] || 'Replace'
  const object = translated.objects[0] || 'furniture'

  // 固定的模板字符串
  let prompt = `${action} the ${object} in Figure 2 with the ${object} from Figure 1. `
  prompt += `Ensure the new ${object} perfectly matches...`

  return prompt
}
```

**问题**:
- 模板写死在代码里，修改需要改代码
- 只支持单个对象
- 图片引用固定（Figure 1/2）
- 无法处理复杂场景

### 新架构（LLM 智能）

```javascript
// ✅ LLM 智能组装
async function buildMetaPrompt({ templateName, userInput, keywords, translatedTerms }) {
  // 1. 从数据库读取模板
  const template = await getPromptTemplate(templateName)

  // 2. 构建 meta-prompt
  const metaPrompt = `
    [系统角色] ${sections.system_role}
    [框架] ${sections.framework}
    [规则] ${sections.rules}
    [示例] ${sections.example}
    [词汇对照] ${buildVocabularyTable(translatedTerms)}
    [用户需求] ${userInput}
    [任务] 生成专业英文提示词...
  `

  return metaPrompt
}

// 3. Gemini LLM 理解并生成
const prompt = await callGeminiText(metaPrompt)
```

**优势**:
- 模板存数据库，修改无需改代码
- LLM 智能理解，支持复杂场景
- 自动判断图片用途
- 灵活可扩展

## 📊 性能和成本

### API 调用次数
- **旧架构**: 1次（图像生成）
- **新架构**: 2次（文本生成 + 图像生成）

### 成本估算（Gemini API）
- 文本生成（gemini-2.5-flash）: ~$0.0001 per request
- 图像生成（gemini-2.5-flash-image）: ~$0.039 per image
- **总成本**: ~$0.0391 per generation（增加 0.26%）

### 延迟
- **新增延迟**: ~1-2秒（LLM 生成提示词）
- **总时长**: ~15-30秒（取决于图片生成）
